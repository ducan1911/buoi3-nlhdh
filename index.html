Khái niệm quan trọng

Phân mảnh file (Fragmentation) là gì?

Khi bạn xóa file và ghi file mới liên tục, ổ đĩa không còn chỗ liền kề để lưu toàn bộ file. Hệ điều hành buộc phải chia file ra nhiều mảnh, rải rác ở các cluster khác nhau trên ổ đĩa.

Với HDD: đầu đọc phải di chuyển cơ học qua lại nhiều vị trí → truy cập chậm hơn rõ rệt. Đây là lý do cần Defragment định kỳ. SSD thì không bị ảnh hưởng vì truy cập điện tử, không cơ học.

Cơ chế nội tại · HDD

Bên trong ổ cứng HDD — Giải phẫu chi tiết

HDD là thiết bị cơ điện tử — dữ liệu được ghi bằng từ tính lên bề mặt đĩa quay. Mỗi thao tác đọc/ghi đều trải qua 4 giai đoạn có thể đo được:

📐

Track & Cylinder

Track: vòng tròn đồng tâm trên mặt đĩa. Cylinder: tập hợp các track ở cùng bán kính trên tất cả các platter — đầu đọc truy cập đồng thời.

⏱️

Seek time là nút thắt cổ chai

Đầu đọc phải di chuyển cơ học đến đúng track mất 3–15ms. Đây là lý do chính khiến HDD thua SSD khi truy cập ngẫu nhiên (random I/O).

①
Seek: Controller gửi lệnh → Actuator Arm di chuyển đầu đọc đến đúng track. Mất 3–15ms tùy vị trí.
②
Rotational Latency: Chờ đĩa quay đến đúng sector cần đọc. Trung bình = ½ vòng → ~4ms ở 7200 RPM.
③
Data Transfer: Đầu đọc cảm nhận từ trường trên mặt đĩa → chuyển thành tín hiệu điện → giải mã thành bit 0/1.
④
Cache: Dữ liệu đọc được lưu vào buffer cache (thường 64–256 MB) của controller để tăng tốc lần đọc tiếp theo.
02
Công nghệ lưu trữ

HDD vs SSD
Ai thắng?

Hai công nghệ lưu trữ hoàn toàn khác nhau về nguyên lý — mỗi loại có ưu thế riêng ở từng tình huống.

HDD

Ổ đĩa cơ (Hard Disk Drive)

Tốc độ đọc tuần tự: ~150 MB/s
  • Đĩa từ quay 5400–7200 RPM
  • Đầu đọc di chuyển cơ học
  • Dung lượng lớn, giá rẻ (40–60 USD/TB)
  • Nhạy cảm với va đập, rung lắc
  • Bị ảnh hưởng bởi phân mảnh
Lưu trữ khối lượng lớn
SSD

Ổ thể rắn (Solid State Drive)

Tốc độ đọc NVMe: ~3000–7000 MB/s
  • Chip NAND flash, không cơ học
  • Truy cập điện tử tức thì
  • Giá cao hơn (~80–120 USD/TB)
  • Bền, im lặng, ít tỏa nhiệt
  • Không bị phân mảnh

Cơ chế nội tại · SSD

Bên trong SSD — Chip NAND Flash hoạt động thế nào?

SSD không có bộ phận cơ học. Dữ liệu được lưu dưới dạng điện tích trong các ô nhớ (cell) bán dẫn. Hiểu nguyên lý này giúp bạn dùng SSD đúng cách và kéo dài tuổi thọ.

⚡
Cell NAND

Đơn vị lưu trữ cơ bản

Mỗi cell là một transistor float-gate giữ điện tích. Mức điện tích khác nhau = giá trị bit khác nhau. Không cần nguồn điện để giữ dữ liệu (non-volatile).

🔗
Block & Page

Cấu trúc tổ chức

Nhiều cell → Page (4–16 KB) — đơn vị ghi nhỏ nhất. Nhiều page → Block (128–512 KB) — đơn vị xóa nhỏ nhất. Không thể xóa từng page riêng lẻ.

①
Write (Ghi): Controller SSD ghi dữ liệu vào các page trống trong block. Ghi rất nhanh vì chỉ cần nạp điện tích vào cell.
②
Erase (Xóa) — điểm quan trọng: NAND Flash không thể ghi đè trực tiếp. Phải xóa cả block trước khi ghi mới. Xóa chậm hơn ghi ~10 lần.
③
Wear Leveling: Controller phân tán đều lượt ghi ra khắp block để tránh mài mòn một vùng quá nhiều. Kéo dài tuổi thọ SSD đáng kể.
④
Garbage Collection: Tiến trình nền thu gom các block có dữ liệu "đã xóa logic" → hợp nhất dữ liệu còn dùng → xóa block cũ → giải phóng block sạch để ghi tiếp. Giữ hiệu năng ổn định.
⑤
TRIM Command: Windows báo cho SSD biết block nào đã xóa → SSD chủ động dọn dẹp sớm hơn → không bị chậm khi đầy. Luôn bật TRIM trên Windows (fsutil behavior query DisableDeleteNotify).
⚠️

SSD cũng có tuổi thọ ghi (TBW)

Mỗi SSD có thông số TBW (Terabytes Written) — ví dụ Samsung 970 EVO 500GB = 300 TBW. Ghi 50 GB/ngày mất ~16 năm để hết TBW. Người dùng bình thường không cần lo, nhưng server hay máy trạm cần chú ý.

03
Định dạng & tổ chức

Định dạng
File System

File system là "ngôn ngữ" mà ổ đĩa dùng để ghi nhớ file nào nằm ở đâu. Khác file system — không đọc được nhau.

NTFS

New Technology File System

Kích thước file tối đa: 16 EB (thực tế không giới hạn)
Partition tối đa: 256 TB
Journaling: Có — tự phục hồi khi mất điện
Phân quyền: Có — kiểm soát ai đọc/ghi
Mã hóa (EFS): Có
Hỗ trợ: Windows (native), macOS (chỉ đọc), Linux (cần driver)
Ổ C: hệ thống Ổ D: trong máy Khuyến nghị
FAT32

File Allocation Table 32-bit

Kích thước file tối đa: 4 GB — đây là giới hạn chết
Partition tối đa: 2 TB
Journaling: Không — dễ mất dữ liệu khi tắt đột ngột
Phân quyền: Không
Hỗ trợ: Mọi hệ điều hành, TV, máy ảnh, game console
USB nhỏ ≤32 GB Thẻ nhớ cũ Không dùng cho file >4 GB
exFAT

Extended FAT — thế hệ mới

Kích thước file tối đa: 16 EB (không giới hạn thực tế)
Partition tối đa: 128 PB
Journaling: Hạn chế
Phân quyền: Không
Hỗ trợ: Windows, macOS 10.6.5+, Linux 5.4+, Android
USB lớn >64 GB Ổ ngoài đa nền tảng Thay thế FAT32
🧭

Công thức chọn định dạng

Ổ cứng bên trong Windows → NTFS  |  USB dùng với nhiều thiết bị và file <4GB → FAT32  |  USB dùng đa nền tảng hoặc file video >4GB → exFAT

Cơ chế nội tại · NTFS

NTFS hoạt động bên trong ra sao? MFT & Journaling

NTFS không chỉ lưu dữ liệu — nó còn theo dõi mọi thứ qua hai cơ chế cốt lõi: Master File Table (bảng chỉ mục toàn bộ file) và Journal (nhật ký giao dịch để chịu lỗi).

🗃️
MFT

Master File Table

Bảng trung tâm lưu siêu dữ liệu của mọi file và thư mục trên phân vùng. Mỗi entry = 1 KB, chứa: tên file, kích thước, timestamp, phân quyền, và địa chỉ cluster chứa dữ liệu thực.

📓
$LogFile

Transaction Journal

Nhật ký ghi trước (write-ahead log). Trước khi thực sự thay đổi MFT, NTFS ghi ý định vào journal. Nếu mất điện giữa chừng, Windows đọc journal để rollback về trạng thái nhất quán.

Cấu trúc một MFT Entry (1024 bytes)
Header
16B
$STANDARD_INFO
ngày tạo, sửa, phân quyền
$FILE_NAME
tên file, parent dir
$SECURITY
ACL, owner
$DATA (runs)
địa chỉ cluster thực
* File nhỏ (<700B) được lưu trực tiếp trong MFT Entry — không tốn cluster riêng (Resident Data)
①
Khi bạn tạo file mới: NTFS tìm cluster trống → tạo MFT entry mới với $DATA chứa địa chỉ các cluster đó → cập nhật $Bitmap đánh dấu cluster đã dùng.
②
Journaling — 3 pha: Log intent → thực hiện thay đổi MFT → Commit vào journal. Nếu crash ở bước 2, Windows chạy chkdsk /f để rollback theo journal.
③
Khi xóa file: NTFS chỉ cập nhật $Bitmap để đánh dấu cluster là trống — dữ liệu thực sự vẫn còn đó cho đến khi bị ghi đè. Đây là lý do phần mềm recovery có thể khôi phục file đã xóa!
④
Phân quyền ACL: Mỗi file có danh sách kiểm soát truy cập (Access Control List). Ví dụ: SYSTEM: Full Control, Administrators: Full Control, Users: Read & Execute. Đây là lý do thư mục System32 từ chối xóa dù bạn là Admin.
🔍

Xem MFT và thông tin NTFS bằng lệnh

Mở CMD với quyền Admin và chạy: fsutil fsinfo ntfsinfo C: — hiện cluster size, tổng MFT size, số MFT entry đã dùng, và nhiều thông tin nội tại khác của NTFS.

Mẹo thực tế

Tại sao nên tách C: và D: riêng biệt?

Khi cần cài lại Windows (format ổ C:), toàn bộ dữ liệu ở ổ D: vẫn nguyên vẹn. Đây là thói quen bắt buộc của người dùng chuyên nghiệp: hệ thống trên C:, dữ liệu trên D:.

Chia ổ đĩa thành C: và D: (Disk Management)

⚠️

Lưu ý trước khi thực hiện

Backup dữ liệu quan trọng. Quá trình Shrink Volume không xóa dữ liệu, nhưng hãy cẩn thận với bước New Simple Volume.

01
Nhấn Win + X → chọn Disk Management (hoặc gõ diskmgmt.msc vào Run)
02
Chuột phải vào ổ C: trong sơ đồ → chọn Shrink Volume…
03
Trong ô "Enter the amount of space to shrink in MB" — nhập lượng MB muốn cắt ra cho D: (ví dụ: 204800 = 200 GB)
04
Nhấn Shrink → đợi xử lý. Vùng màu đen "Unallocated" xuất hiện bên phải C:
05
Chuột phải vào vùng Unallocated → New Simple Volume… → theo wizard: gán tên ổ D:, chọn định dạng NTFS, nhấn Finish

Bài thực hành 4

Kiểm tra phân quyền file hệ thống & vì sao không xóa được

Thực hành trực tiếp xem ACL và hiểu cơ chế bảo vệ file trong ổ C:

⚠️

Bài thực hành quan sát — không chỉnh sửa quyền

Chỉ xem, không thay đổi. Thay đổi phân quyền thư mục hệ thống có thể gây lỗ hổng bảo mật hoặc làm hỏng Windows.

Bước 1 — Thử xóa file hệ thống (quan sát thông báo lỗi):

File Explorer → C:\Windows\System32 → thử xóa bất kỳ file .dll nào → quan sát thông báo từ chối

Bước 2 — Xem phân quyền ACL bằng giao diện đồ họa:

Chuột phải vào C:\Windows\System32 → Properties → tab Security

→ Quan sát danh sách: SYSTEM, Administrators, TrustedInstaller, Users — và cột quyền của từng nhóm (Allow/Deny)

Bước 3 — Xem phân quyền bằng CMD (chi tiết hơn):

icacls C:\Windows\System32
icacls C:\Windows\System32\notepad.exe

Bước 4 — Kiểm tra NTFS cluster size và thông tin MFT:

fsutil fsinfo ntfsinfo C:
fsutil volume diskfree C:

Bước 5 — Xem trạng thái TRIM trên SSD:

fsutil behavior query DisableDeleteNotify

→ Kết quả = 0: TRIM đang bật (tốt). Kết quả = 1: TRIM tắt (không tốt cho SSD)
